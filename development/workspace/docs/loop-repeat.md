# Repeat a demonstrated loop

For a repeatable mana-ability combo, perform the same complete cycle twice. When the nonmana board position returns unchanged and both cycles produce the same positive mana gain, Arena's native **X selector** appears. Choose an **additional** count from 1 to 1000 with the original ±1/±5 controls, then confirm **X = count**. Choosing 100 means 100 more complete cycles, in addition to the cycles already performed.

To stack an activated ability repeatedly, activate it while retaining priority. If its costs leave a repeatable position, the panel offers **Stack repeats**. Each repetition pays the real current cost and creates another real Forge stack entry. Use the normal Resolve/Pass control when ready to resolve them. Mana abilities resolve immediately under normal Magic rules; they are not artificially placed on the stack.

For a deterministic life-gain ability cycle, demonstrate the same complete cycle twice. The **Life loop** panel appears only when each cycle gains the same amount of your life, changes mana by the same amount, and returns every other tracked board element unchanged. Every repeat pays its current costs. For example, Staff of Domination's gain-life and self-untap abilities spend three mana per additional life; the batch stops when the next actual activation is unaffordable. It does not create free life or mana.

The native blue **Cancel** button prevents further submissions and closes the expanded controls. Already submitted actions and costs remain applied. If the current action has opened a choice, finish that choice normally. A changed position, decision, target, cost, unavailable action, unexpected coin flip or incomplete request stops the batch rather than retrying it. Opponent responses are never passed on their behalf.

Once a sequence is detected, the selector can stay open through ordinary untap resolution and preparation. While a batch runs, the selector gives way to progress and Cancel. Completion, interruption or cancellation closes the expanded controls. A native blue **Repeat combo** button reopens the selector when the sequence is available, preserving the chosen count. A real spell's numeric choice temporarily takes precedence over the repeat selector. The next match starts with fresh hidden controls.

Automatic empty priority passes are recorded too. Omitting those actual accepted passes made a sequence learned with normal auto-resolution fail when replay retained priority. Recording them preserves the same costs, responses and position checks without guessing or skipping resolution.

This version recognizes deterministic activated/mana-ability sequences up to 16 submitted actions, including explicit color and target choices. It does not solve arbitrary spell, sacrifice, random or library-changing loops, or cycles that change other board objects. The interface appears only after a repeatable position is demonstrated. A batch has its own identity, so a delayed result or Stop from an earlier batch cannot count as the current one.

Real Forge/native-handler checks cover Zaxara with Freed from the Real or Pemmin's Aura; Sanctum Weaver, Bloom Tender, Faeburrow Elder and adapted Incubation Druid with Freed; and Marwyn or Circle of Dreams Druid with Staff of Domination. Staff life-gain tests also verify actual mana payment, distinct successive batches and insufficient resources. These are specific tested positions, not universal combo certification.

Separate two-human native-handler runs cover both host-owned and guest-owned repetition over HTTP loopback: ten complete cycles, explicit opposing response windows, Stop while the opponent holds priority, and interruption by a real opposing bounce spell. A complete host-owned run over an actual public HTTPS tunnel passed the same checks. Earlier timeout and DNS failures remain recorded; the final endpoint required DNS readiness before joining. This is bounded network/handler coverage, not two rendered clients on separate PCs or a general internet-reliability guarantee. Ordinary actions, opposing decisions and animations are never skipped to accelerate a batch.

Developer checks: `ForgeBackend/verify_recorded_loops.py`, `verify_loop_combos.py`, `verify_loop_life.py` and `verify_loop_multiplayer.py` drive actual Forge and shipped native handlers in isolated research runtimes. `LoopRepeatProbe` replays an observed trace to test guard rejection; its synthetic mutations are not positive gameplay evidence. No proprietary game code or assets are included in these tests.
