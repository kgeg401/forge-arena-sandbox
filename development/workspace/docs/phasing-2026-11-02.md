# Phasing presentation checkpoint

Teferi's Protection previously disappeared permanents from the exported battlefield. The renderer interpreted that omission as deletion, even though Forge still held the same phased-out cards. This update keeps physical battlefield membership and exports each card's actual phased state.

The adapter retains each native identity and emits the original phase-out/phase-in annotations. A phased card uses the original synthetic PhasedOut realm (12); it remains listed in its physical battlefield's membership. The synthetic realm is owned by the original parser and must not be explicitly recreated. Phasing does not create a zone-transfer event or a new card identity. Forge still owns targeting, mana availability, untapping, and all game rules.

## Verified behavior

- Two native-handler sequences cast and resolve the real spell, advance through the opponent's turn, and return the permanents through the next actual untap. Both preserve identities; the larger case also preserves two tokens, counters, the Greaves attachment, haste, and shroud.
- Every affected original native model moves Battlefield → PhasedOut → Battlefield, with one event each way and no false deletion.
- A targeted Slip Out the Back sequence phases only its real creature and indirectly attached Swiftfoot Boots. The Islands remain usable, and the creature returns with its actual new counter, attachment, haste, and hexproof. Three focused native cases cover 28 assertions in total.
- A rendered original-client sequence phases three Plains and Grizzly Bears, holds at a real playable Forest, plays that new land, and returns the original four permanents on the next untap. The native phasing visuals appear and clear; the new Forest remains separate. No intermediate state, clock, rules result, or resource was injected.

`ForgeBackend/verify_phasing.py` drives actual independent Forge rules plus the owned native parser/handlers. All 24 prior focused card/effect cases (128 assertions) also pass with the integrated changes. The private rendered capture is supplemental evidence, not a complete-match or full-catalogue certification. Targeted phasing, opponent-controlled phasing, and reconnecting mid-phasing have not yet received equivalent rendered checks.

The user installation and profiles were not updated. These changes and checks are local development work; original assets and private reverse-engineering excerpts are excluded from source publication.
