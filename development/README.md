# Development sources and catalogue tools

`workspace/` mirrors the authored local development workspace. The snapshot
manifest records the original commit and SHA-256 for every included source file.
The player-facing packaged source remains under `../client/`; download the
Windows release ZIP to install, rather than running this development tree.

The full workspace includes rules/native adapter sources, catalogue mapping,
mechanic-family qualification, generated scenario suites, bounded cold/warm
batch runners, independent evidence validation, installed acceptance checks,
installer/updater fixtures, disabled research and dated development notes.

No owned Arena assets/assemblies, private profiles, raw runtime dumps or full
native evidence archives are included. Those tests require compatible owned
Arena files and the pinned Forge distribution. Historical documentation retains
local Windows example paths and dated counts; use the current public README and
supported list for release status. Review paths and supply explicit runtime
configuration before running any research tool on another PC.

The production policy is the370-name `ForgeBackend/bridge_support.json`.
`ForgeBackend/draft_policies/paradox-engine.json` is explicitly research-only.
Its verifier and practice input preserve unfinished work, not passing support.
A source match, construction pass or generated test cannot grant admission.

For player installation/build details see [the developer guide](../docs/DEVELOPMENT.md).
The headless GitHub workflow checks installer, updates, coordinator and display
fixtures without game assets; it cannot prove native gameplay or recipient-PC
installation. The full native/rules evidence has separate documented limits.
